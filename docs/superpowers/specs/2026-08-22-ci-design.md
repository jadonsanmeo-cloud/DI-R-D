# CI Design

## Goal

Add a GitHub Actions workflow that gives pull requests and pushes to `main`
fast, repeatable formatting, linting, type-checking, and unit-test feedback.

## Scope

The workflow will run on GitHub-hosted Ubuntu runners for pull requests to
`main` and pushes to `main`. It will use Python 3.11, the repository's minimum
supported Python version, and install dependencies with `uv`.

The workflow will use ephemeral, pinned tool versions for `pytest`, `ruff`, and
`mypy`; it will not add development dependencies to the project manifests.

## Checks

The workflow will contain separate jobs for:

1. Formatting and linting with `ruff format --check` and `ruff check`.
2. Type checking with `mypy` over both package source trees.
3. Tests with `pytest` over the SDK tests, API tests, and repository-level
   tests that do not require sibling repositories.

## Test Boundary

`packages/api/tests/test_stateless_genreport_cutover.py` dynamically imports
the sibling `GenReport` checkout. GitHub's standalone checkout of this
repository does not include that directory, so CI will explicitly exclude this
integration test. The remaining API and SDK tests run without external
services.

## Non-Goals

- Check out or authenticate to sibling private repositories.
- Run deployment, container publishing, or release jobs.
- Add a database or external service dependency to CI.

## Failure Behavior

Each job fails the workflow on a non-zero command exit. GitHub Actions retains
the full command logs so contributors can identify failing files or tests.
